# CLAUDE.md — 에이전트 실행 규칙 (정본)

> 이 파일은 **AI 에이전트가 매 세션 처음에 읽는 규칙서**입니다.
> 사람이 읽는 설명은 한국어, 에이전트가 실행하는 **명령어는 영어로 고정**합니다.
> 이 문서가 **정본(Single Source of Truth)** 이며, `AGENTS.md` 는 이 문서를 가리키는 요약본입니다.

---

## 1. 이 위키의 목적

박상익의 실무(출장음식 · 유튜브 · BNI · 홈페이지 개발)에서
**여러 AI 에이전트가 같은 업무 맥락을 공유**하기 위한 저장소입니다.

세션이 끝나면 에이전트의 기억은 사라집니다. 이 위키가 **에이전트의 장기 기억**입니다.

---

## 2. 3개 영역 분리 원칙 (맥락 오염 방지의 핵심)

| 영역 | 폴더 | 성격 | 수정 가능? |
|---|---|---|---|
| **Raw** | `raw/` | **원본 자료·회의록·대화 로그·외부 문서** | ❌ **불변. 절대 편집 금지** |
| **Conversations** | `conversations/` | 세션 대화 기록·중간 사고 과정 | ❌ 추가만 가능(append-only) |
| **Wiki** | `wiki/` | **Raw를 바탕으로 정리된** 실행 규칙·의사결정·프로젝트 맥락·반복 재사용 지식 | ✅ 편집·갱신 가능 |

### Raw 영역에 들어가는 것 (변경하면 안 되는 불변 자료)
회의록 · 대화 로그 · 외부 문서 · 계약서 · 견적서 · 기사 · 경쟁사 자료 · 고객이 보낸 원문

### Wiki 영역에 들어가는 것 (Raw를 바탕으로 정리된 것만)
실행 규칙 · 의사결정과 그 근거 · 프로젝트 맥락 · 반복 재사용 가능한 지식

> **Wiki 는 Raw 없이 존재할 수 없다.** 모든 Wiki 노트는 `source:` 로 근거를 가리켜야 한다.

### 불변성 보증 장치 (문서가 아니라 실제 검사)
`raw/.manifest` 에 모든 원본의 **지문(SHA256 해시)** 이 기록되어 있다.
- 검증: `bash tools/raw-guard.sh verify` → 한 글자라도 바뀌면 **🚨 로 잡힌다**
- 신규 등록: `bash tools/raw-guard.sh seal` → `ingest` 직후 반드시 실행
- `lint` 11번 검사가 이것을 자동으로 돌린다

### 절대 규칙 (NEVER)
1. **`raw/` 안의 파일을 수정하거나 삭제하지 않는다.** 정정이 필요하면 새 파일을 추가한다.
2. **`conversations/` 의 내용을 그대로 `wiki/` 로 복사하지 않는다.** 반드시 §4 의 5-필터를 거쳐 재작성한다.
3. **검증되지 않은 추측을 `wiki/` 에 쓰지 않는다.** 추측은 반드시 `> 추정입니다` 표기와 함께 `raw/` 또는 `conversations/` 에만 남긴다.
4. **출처(`source`) 없는 결정은 `wiki/` 에 쓰지 않는다.**

## 3. 명령어 (영어 고정) — 트리거와 동작

### 3.0 명령어 입출력 한눈에 보기 (정본 표)

**에이전트는 이 표를 기준으로 동작한다.** 아래 세부 절과 충돌하면 이 표가 우선한다.

| 명령어 (영어 고정) | 언제 실행하나 | **읽는 파일** | **쓰는 파일** | 절대 하지 않는 것 |
|---|---|---|---|---|
| `reference` | 세션 시작 / 맥락이 필요할 때 | `index.md` → `log.md`(최근 10줄) → 주제 관련 `wiki/` 노트 | **없음 (읽기 전용)** | 없는 내용을 지어내기 |
| `save` | 세션 종료 시 **자동** / 사용자 요청 시 | `index.md`, 관련 `wiki/` 노트, 현재 대화 | ① `conversations/` **항상** ② `wiki/` **5-필터 통과분만** ③ `log.md` ④ `index.md` | 필터 미통과분을 `wiki/` 에 쓰기 |
| `ingest` | 원본 자료(회의록·문서·링크)를 받았을 때 | 사용자가 준 원본 | `raw/<분류>/` **원문 그대로** + `log.md` | 요약·수정해서 저장하기, 자동 승격 |
| `query` | 과거 결정·정보를 물을 때 | `wiki/` → 없으면 `raw/` → `conversations/` | **없음** (+ `log.md` 한 줄) | 인용 없이 답하기 |
| `lint` | 정기 점검 / 위키가 지저분할 때 | `wiki/` 전체 | **없음 (보고만)** | 파일 자동 수정·삭제 |

### 3.0.1 트리거 인식 규칙

1. **영어 명령어를 그대로 입력**해도 동작한다. (`save`, `lint` 등)
2. 한국어 문장은 **완전히 일치하지 않아도** 아래 조합이면 인식한다.
   - `옵시디언` 또는 `위키` + `저장/기록` → **`save`**
   - `옵시디언` 또는 `위키` + `참조/불러와/맥락` → **`reference`**
   - `원본/raw` + `넣어/저장` → **`ingest`**
   - `찾아/검색/전에 뭐라고` → **`query`**
   - `점검/린트/정리` → **`lint`**
3. **어느 명령인지 모호하면 실행하지 말고 되묻는다.** 잘못 실행해 `wiki/` 를 오염시키는 것보다 낫다.
4. 명령 실행 전에 **어떤 명령으로 이해했는지 한 줄로 밝힌다.**

---

에이전트는 아래 **영어 명령어**를 정식 이름으로 인식하고,
**한국어 트리거 문장**이 들어와도 같은 동작을 수행한다.

### 3.1 `save` — 이번 작업을 위키에 저장
- **한국어 트리거**: `이번 작업 내용 옵시디언에 저장해줘` / `옵시디언 저장` / `위키에 저장해줘`
- **읽는 파일**: `index.md`, `wiki/` 의 관련 노트, 현재 세션 대화
- **쓰는 파일**:
  1. `conversations/YYYY-MM-DD_주제.md` — **항상** 기록 (필터와 무관)
  2. `wiki/<영역>/<제목>.md` — **§4 의 5-필터를 통과한 항목만**
  3. `log.md` — 맨 위에 한 줄 추가 (§7-3 형식)
  4. `index.md` — 새 노트가 생겼으면 링크 추가
- **절차**:
  1. 이번 세션에서 나온 내용을 항목별로 쪼갠다.
  2. 각 항목에 5-필터를 적용하고, **통과/탈락 사유를 사람에게 보고**한다.
  3. 통과 항목만 `wiki/` 에 승격(promote)한다. 탈락 항목은 `conversations/` 에만 남긴다.
  4. 저장 결과를 표로 요약해 보고한다.

### 3.2 `reference` — 위키를 읽어 맥락 복원
- **한국어 트리거**: `옵시디언 참조` / `위키 참조해줘` / `맥락 불러와줘`
- **읽는 파일**: `index.md` → `log.md`(최근 10줄) → 주제 관련 `wiki/` 노트
- **쓰는 파일**: **없음 (읽기 전용)**
- **절차**:
  1. `index.md` 로 전체 지도를 파악한다.
  2. `log.md` 최근 기록으로 "어디까지 했는지"를 파악한다.
  3. 이번 대화 주제와 관련된 `wiki/` 노트를 연다.
  4. **불러온 노트 목록과 핵심 3줄 요약을 먼저 보고**한 뒤 작업을 시작한다.
  5. 관련 노트가 없으면 "관련 위키 없음"이라고 명시한다. **지어내지 않는다.**

### 3.3 `ingest` — 원본 자료를 Raw에 넣기
- **한국어 트리거**: `이 자료 원본으로 넣어줘` / `옵시디언에 원본 저장` / `raw에 넣어줘`
- **읽는 파일**: 사용자가 준 원본(붙여넣기, 파일, URL)
- **쓰는 파일**: `raw/<분류>/YYYY-MM-DD_출처_제목.md` — 분류는 `meetings` / `documents` / `sources`
- **절차**:
  1. 원본을 **한 글자도 요약·수정하지 않고** 그대로 저장한다.
  2. 맨 위에 frontmatter(§5)로 출처·날짜·수집자만 덧붙인다.
  3. **분류(triage)**: 이 원본이 건드리는 기존 `wiki/` 노트를 전부 찾아 나열한다.
  4. **기존 노트와 충돌하는 내용이 있으면 §6-8 의 모순 블록으로 기록**한다. 조용히 덮어쓰지 않는다.
  5. **`bash tools/raw-guard.sh seal` 을 실행해 지문을 등록한다.** ← 생략 금지
  6. `log.md` 에 `ingest` 한 줄을 남긴다.
  7. 승격 여부를 묻는다. **자동 승격 금지.**

### 3.4 `query` — 위키에서 찾기
- **한국어 트리거**: `위키에서 찾아줘` / `옵시디언에서 검색` / `전에 뭐라고 정했지?`
- **읽는 파일**: `wiki/` 전체 → 없으면 `raw/`, `conversations/`
- **쓰는 파일**: 없음
- **절차**:
  1. `wiki/` 를 먼저 찾고, 없으면 `raw/` → `conversations/` 순으로 넓힌다.
  2. **모든 문장에 인용을 붙인다.** 인용 없는 답변은 금지.
  3. 찾지 못하면 "위키에 없음"이라고 답하고 **지어내지 않는다.**
  4. `log.md` 에 `query` 한 줄을 남긴다.
- **인용 형식 (필수)**
  ```
  답변 문장. [출처: wiki/10-출장음식/사업-개요.md]
  ```
  - `wiki/` 근거면 그대로 인용한다.
  - `raw/` 나 `conversations/` 에서만 찾았으면 **"아직 위키에 정리되지 않음"** 을 함께 밝힌다.
  - 답을 만들다 알게 된 값진 사실은 **승격을 제안**한다. (5-필터 적용)

### 3.5 `lint` — 위키 건강검진
- **한국어 트리거**: `옵시디언 점검해줘` / `위키 정리해줘` / `린트 돌려줘`
- **읽는 파일**: `wiki/` 전체
- **쓰는 파일**: 없음 (**보고만 한다. 자동 수정 금지**)
- **점검 항목**: §6 참조

## 4. `save` 5-필터 (위키 승격 관문)

`wiki/` 에 저장하려면 **아래 5개 중 최소 1개를 반드시 통과**해야 한다.

| # | 질문 | 통과 예시 |
|---|---|---|
| **1** | 향후 실무에 **반복 재사용**될 데이터인가? | 쇼츠 대본 포맷, 단가표 |
| **2** | 다른 에이전트·동료가 **인수인계** 받으려면 반드시 읽어야 하는가? | 프로젝트 현재 상태 |
| **3** | **의사결정의 근거와 결정권자**를 나중에 추적할 필요가 있는가? | "왜 이 채널명으로 정했나" |
| **4** | **실패한 방식**이라 다시 시도하면 안 되는 리스크 정보인가? | "이 썸네일 방식은 조회수 폭락" |
| **5** | 팀 전체가 맞춰야 하는 **공통 규칙·디자인 가이드**인가? | 톤앤매너, 금지 표현 |

### 탈락 처리
5개 중 **하나도 해당하지 않으면 `wiki/` 승격 금지**. 아래로 보낸다.
- 일회성 답변 → `conversations/`
- 사소한 중간 생각 → `conversations/`
- 검증되지 않은 추측 → `conversations/` (반드시 `> 추정입니다` 표기)
- 외부 원문·회의록 → `raw/`

### 필터 판정 절차 (save 실행 시 반드시 이 순서로)

1. **쪼갠다** — 이번 세션 내용을 항목 단위로 나눈다. 뭉뚱그리면 필터가 무력해진다.
2. **묻는다** — 각 항목에 5개 질문을 **하나씩** 던진다.
3. **기록한다** — 통과한 항목은 노트에 두 가지를 반드시 쓴다.
   - `filters: [번호]` — 어떤 필터를 통과했나
   - `filter_reason: 한 줄` — **왜** 통과했나
   > `filter_reason` 이 없으면 `lint` 3번 검사가 잡아낸다. 번호만 적고 넘어갈 수 없다.
4. **관문을 통과시킨다** — `wiki/` 로 옮기기 **전에** 반드시 실행한다.
   ```bash
   bash tools/promote-check.sh <노트파일>
   ```
   - 🟢 **승격 가능** → `wiki/` 로 옮긴다
   - 🔴 **승격 차단** → 고치거나 `conversations/` 에만 남긴다. **차단을 무시하고 옮기지 않는다.**
5. **버린다** — 하나도 통과 못 하면 `conversations/` 로만 보낸다. 예외 없다.
6. **보고한다** — 통과·탈락을 표로 사람에게 보여준다.

### 승격 관문 — `tools/promote-check.sh`

승격 금지 목록과 5-필터를 **사람의 기억이 아니라 스크립트가** 검사한다.
3단계를 모두 통과해야만 `wiki/` 에 들어갈 수 있다.

| 단계 | 무엇을 보나 | 걸리면 |
|---|---|---|
| 1단계 | 검증 안 된 추측 / 대화 원문 복붙 | 🔴 차단 → `conversations/` |
| 2단계 | `filters` 기재·유효성, `filter_reason` 기재 | 🔴 차단 → 필터 재적용 |
| 3단계 | `source` 존재 및 경로 유효성 | 🔴 차단 → 먼저 `ingest` |

### 승격 금지 목록 (필터를 논할 것도 없이 `wiki/` 진입 불가)

| 유형 | 어디로 보내나 |
|---|---|
| 일회성 답변 (이번에만 쓰는 계산·요약) | `conversations/` |
| 사소한 중간 생각·브레인스토밍 | `conversations/` |
| 검증되지 않은 추측 | `conversations/` + `> 추정입니다` 표기 |
| 외부 원문·회의록 그대로 | `raw/` |
| 대화 내용을 **복사·붙여넣기** 한 것 | 재작성 전까지 승격 불가 (`lint` 12번이 탐지) |

### 보고 형식 (save 실행 시 반드시 출력)
```
| 항목 | 통과 필터 | 저장 위치 |
|---|---|---|
| 쇼츠 러닝타임 2분30초 확정 | 1, 5 | wiki/20-유튜브/별빛마실-채널-가이드.md |
| 오늘 떠올린 아이디어 스케치 | 없음 | conversations/ (승격 안 함) |
```

## 5. 파일 작성 규칙

### frontmatter (모든 노트 맨 위에 필수)
```yaml
---
type: wiki          # wiki | raw | conversation | decision
title: 노트 제목
area: 유튜브         # 출장음식 | 유튜브 | BNI | 홈페이지 | 공통
status: 확정         # 확정 | 검토중 | 폐기
owner: 박상익        # 결정권자 (필터 3용)
source: raw/meetings/2026-09-05_회의.md   # 근거 위치. 없으면 wiki 저장 금지
created: 2026-09-05
updated: 2026-09-05
filters: [1, 5]     # 통과한 5-필터 번호
tags: [쇼츠, 가이드]
---
```

### 파일명
- `raw/` : `YYYY-MM-DD_출처_제목.md`
- `conversations/` : `YYYY-MM-DD_주제.md`
- `wiki/` : `주제-이름.md` (날짜 없음 — 계속 갱신되는 살아있는 문서)

### 언어 — 한글·영문 혼용 기준

| 구분 | 언어 | 예시 |
|---|---|---|
| 사람이 읽고 편집하는 내용 | **한국어** | 톤앤매너, 금지 표현, 지침, 기획 기준, 설명문 |
| 에이전트가 실행하는 키워드 | **영어 고정** | `save` `reference` `ingest` `query` `lint` |
| frontmatter 키 | **영어 고정** | `type` `title` `area` `status` `owner` `source` `filters` |
| 폴더명 | **영어 고정** | `raw` `wiki` `conversations` `templates` `tools` |
| 노트 파일명 | **한국어 허용** | `별빛마실-채널-가이드.md` |

**이유**: 사람은 한국어로 읽어야 편하고, 에이전트는 영어 키워드가 흔들리지 않아야 매 세션 같게 동작한다.
상세: [[wiki/90-공통규칙/언어-규칙]]

## 6. `lint` 점검 항목

| # | 점검 | 판정 기준 | 조치 제안 |
|---|---|---|---|
| 1 | **검증 안 된 추측** | 본문에 `추정`, `아마`, `~일 듯`, `확인 필요` 포함 | `conversations/` 로 강등 |
| 2 | **출처 없는 결정** | frontmatter `source` 가 비었거나 존재하지 않는 경로 | 출처 보강 또는 강등 |
| 3 | **중복 정보** | 제목이 같거나, **본문 문장이 70% 이상 겹침** (`tools/dupcheck.py`) | 통합 후 링크 |
| 4 | **오래된 규칙** | `updated` 가 **180일 이상** 지났고 `status: 확정` | 재확인 요청 |
| 5 | **필터 미기재** | `filters` 가 비어 있음 | 5-필터 재적용 |
| 6 | **끊어진 링크** | `[[...]]` 대상 파일 없음 | 링크 수정 |
| 7 | **고아 노트** | `index.md` 어디에서도 링크되지 않음 | index 등록 |
| 8 | **모순** | 같은 주제를 다룬 두 노트가 서로 다른 값·결론을 말함 | §6-8 모순 블록으로 기록 후 사람이 판정 |
| 9 | **상호참조 누락** | 위키링크가 하나도 없는 노트 (지식이 고립됨) | 관련 노트와 연결 |
| 10 | **조사 공백** | 미체크 항목 `- [ ]` 이 남아 있음 | 무엇을 더 조사해야 하는지 보고 |

**lint 는 보고만 한다. 파일을 자동으로 고치거나 지우지 않는다.**
수정은 사람이 승인한 뒤 별도 요청으로 수행한다.

### §6-8. 모순을 발견했을 때 (조용히 덮어쓰기 금지)

새 자료가 기존 노트와 충돌하면 **어느 쪽이 맞는지 에이전트가 임의로 판정하지 않는다.**
해당 노트 하단에 아래 블록을 추가하고 사람의 판정을 기다린다.

```markdown
## ⚠️ 모순 기록
| 항목 | 기존 내용 | 새 자료 | 출처 | 판정 |
|---|---|---|---|---|
| 1인 단가 | 2만원 | 2만 5천원 | raw/documents/2026-09-10_견적서.md | **미판정** |
```

판정이 끝나면 본문을 고치고, 모순 블록은 **기록으로 남겨둔다.**
"예전에 이렇게 알고 있었다"는 사실 자체가 필터 3(의사결정 추적) 자산이기 때문이다.

## 7. 세션 시작·종료 루틴

### 세션 시작
사용자가 `옵시디언 참조` 라고 하면 → `reference` 실행.

### 세션 종료 — **자동 저장 (사용자 설정: 2026-09-05)**
대화가 마무리될 때 **사용자가 명령하지 않아도 에이전트가 스스로 `save` 를 실행**한다.

1. `conversations/` 에 세션 기록을 남긴다. (항상)
2. 5-필터를 적용해 **통과분만** `wiki/` 로 승격한다.
3. `log.md` 와 `index.md` 를 갱신한다.
4. **저장 직후 승격 목록을 표로 보고한다.** ← 생략 금지

### §7-3. `log.md` 기록 형식 — 5개 명령 **전부** 남긴다

`save` 뿐 아니라 `reference` · `ingest` · `query` · `lint` 를 실행할 때마다 한 줄씩 남긴다.
`log.md` 는 **추가만 가능(append-only)** 하며, 기존 줄은 절대 수정하지 않는다.

```
| 2026-09-05 | ingest | 추석 행사 견적서 원본 수집 | - | raw/documents/... |
| 2026-09-05 | lint   | 경고 0건                  | - | -                  |
```
열 순서: `날짜 | 명령 | 내용 | 위키 승격 건수 | 관련 파일`

### 되돌리기 (자동 저장의 안전장치)
보고를 본 사용자가 `그건 빼줘` / `승격 취소` 라고 하면
해당 노트를 **즉시 `wiki/` 에서 내리고 `conversations/` 로 강등**한다.

> 자동 저장이라도 **5-필터는 그대로 적용된다.** 필터를 통과 못 한 잡동사니는 여전히 `wiki/` 에 들어가지 못한다.
