# 6번 — 바이브코딩 위키 복습

노트는 쌓이는데 **다시 읽지 않는다.** 이 스킬은 쌓인 노트를 꺼내 보게 만든다.

## 이 스킬의 목적

사용자는 바이브코딩을 배우는 중이고, 5번(`vibe-coding-save`)으로 작업 노트를
꾸준히 남기고 있다. 그런데 **쓰기만 하고 읽지 않으면 기억에 남지 않는다.**

읽어 주는 것만으로는 부족하다. 기억은 **다시 읽을 때가 아니라 꺼낼 때** 남는다.
그래서 이 스킬은 요약본을 보여주는 데서 그치지 않고 **문제를 낸다.**

## 1단계 — 노트가 있는 볼트와 목록 찾기

볼트는 여러 개일 수 있고, 기억해 둔 볼트가 위키를 가진 볼트가 아닐 수 있다.
`obsidian-save` 스킬의 판별 함수를 그대로 쓴다(직접 폴더를 뒤지지 않는다).

```bash
python - <<'PY'
import sys, pathlib
sys.stdout.reconfigure(encoding="utf-8")
sys.path.insert(0, str(pathlib.Path.home() / ".claude" / "skills" / "obsidian-save"))
try:
    from obsidian_save import detect_vaults, vault_has_folder
except ImportError:
    print("설치된 obsidian_save.py 가 옛 버전입니다(vault_has_folder 없음).")
    print("C:/dev/park-obsidian-save 에서 스킬설치.bat 을 한 번 실행한 뒤 다시 해주세요.")
    raise SystemExit(1)
FOLDER = "바이브코딩-위키"
hits = [v for v in detect_vaults() if vault_has_folder(v, FOLDER)]
for v in hits:
    d = v if v.name == FOLDER else v / FOLDER
    notes = sorted(p.name for p in d.glob("*.md"))
    print(f"{d}  ({len(notes)}장)")
    for n in notes:
        print("  ", n)
if not hits:
    print("위키 폴더를 가진 볼트를 찾지 못했습니다. --list-vaults 로 확인하세요.")
PY
```

> **`vault_has_folder 없음` 이 나오면** 설치본이 옛 버전이다. 이 스킬은 `obsidian-save`
> 의 볼트 판별 기능에 기대므로, `스킬설치.bat` 을 한 번 돌려야 동작한다. 사용자에게
> 그 문장을 그대로 전하고, 임의로 폴더를 직접 뒤지는 방식으로 우회하지 않는다 —
> 우회하면 엉뚱한 볼트의 노트를 복습하게 된다.

**볼트가 둘 이상 나오면 멈추고 사용자에게 묻는다.** 어느 쪽 기록을 복습할지는
기계가 정할 수 없다. 하나도 없으면 폴더 이름을 확인한다(새로 만들지 않는다).

## 2단계 — 읽을 범위 정하기

**34장을 전부 읽지 않는다.** 노트 한 장이 길어서 전부 읽으면 느리고, 정작
복습에 쓰는 것은 일부다. 각 노트에서 이 두 절만 뽑아 읽는다.

- `## 막혔던 것과 해결법` 표 — 실제로 겪은 문제와 원인
- `## 배운 것` 목록 — 그때 정리한 교훈

```bash
# 예: 각 노트에서 두 절만 뽑아 보기 (파일 하나)
sed -n '/^## 막혔던 것과 해결법/,/^## /p; /^## 배운 것/,/^## /p' "노트경로"
```

사용자가 범위를 말하면 따른다("최근 5장만", "사진 관련만"). 말이 없으면
**최근 10장 + 사용자가 지난번 복습에서 틀린 주제**를 기본으로 한다.

## 3단계 — 주제별로 묶기

날짜순 목록은 찾기 어렵다. **4~7개 주제**로 묶고, 각 주제에 노트 번호를 붙인다.
주제 이름은 노트 제목에서 가져오되, 사용자가 쓰는 말로 적는다(예: "도메인·주소",
"사진", "견적서", "배포", "작업 습관").

묶을 때 두 가지를 반드시 표시한다.

- **반복된 실수** — 서로 다른 노트에 같은 원인이 두 번 이상 나오면 ⚠️ 로 묶는다.
  이것이 복습에서 가장 값진 정보다. 예: 캐시 번호를 안 올려 옛 화면이 보인 일,
  측정 도구가 조건을 안 만들어 없는 버그를 쫓은 일.
- **아직 안 한 것** — 노트의 `## 다음에 할 일` 체크박스 중 지금도 안 된 것.
  가능하면 실제로 확인한다(파일이 있는지, 명령이 되는지). **확인하지 않았으면
  "확인 안 함"이라고 적는다** — 했는지 안 했는지 모르는 것을 "안 했다"고 적지 않는다.

## 4단계 — 문제 내기 (핵심)

**3~5문제.** 한 번에 **한 문제씩** 내고 답을 기다린다. 다 늘어놓지 않는다.

문제 만드는 규칙:

- **실제로 겪은 일에서만 낸다.** 일반 상식 문제(`HTML 이 무엇의 약자인가`)는 내지 않는다.
  사장님이 겪은 일이라야 기억에 걸린다.
- **증상 → 원인**을 묻는다. 정답이 노트 안에 있어야 한다.
  예: "사진을 바꿨는데 손님 휴대폰에는 옛 사진이 보입니다. 왜일까요?"
- **정답 표기**를 미리 정해 둔다. 채점은 글자 맞추기가 아니라 **뜻이 맞으면 정답**이다.
- 틀리면 **정답 + 그 노트 번호**를 알려주고 넘어간다. 다시 묻지 않는다.
- 사용자가 "모르겠다", "답 알려줘" 라고 하면 **바로 알려준다.** 뜸들이지 않는다.
- 사장님은 개발자가 아니다. **용어를 묻지 말고 상황을 묻는다.**

마지막에 몇 개 맞혔는지 한 줄로 알린다. 점수로 평가하지 않는다 —
**틀린 문제가 다음에 볼 곳**이라는 뜻으로만 쓴다.

## 5단계 — 복습 노트 저장

`obsidian-save` 의 스크립트로 저장한다. 본문은 파일에 쓴 뒤 `--file` 로 넘긴다.

```bash
python ~/.claude/skills/obsidian-save/obsidian_save.py \
  --title "복습-2026-09-18" \
  --folder "바이브코딩-위키" \
  --tags "바이브코딩,학습,복습" \
  --file "<본문파일경로>"
```

- **제목은 `복습-날짜`** 형태. 위키 노트와 한눈에 구분된다.
- **`--auto-number` 를 쓰지 않는다.** 복습 노트가 위키 번호(35, 36…)를 가져가면
  작업 노트의 번호가 끊긴다. 같은 폴더에 두되 번호는 작업 노트만 쓴다.
- 같은 날 두 번 복습해도 괜찮다 — 스크립트가 `복습-2026-09-18 2.md` 로 만든다.

복습 노트 본문 틀:

```markdown
## 이번에 되짚은 범위
(몇 장, 어느 노트인지)

## 주제별 정리
### 도메인·주소  [[33-...]] [[34-...]]
- 한 줄씩

## ⚠️ 두 번 이상 반복된 실수
| 무슨 일 | 몇 번 | 어느 노트 | 지금은 막혀 있나 |
| --- | --- | --- | --- |

## 오늘 문제와 답
| 문제 | 내 답 | 정답 | 노트 |
| --- | --- | --- | --- |

## 아직 안 한 일
- [ ] (노트에서 가져온 것 + 지금도 안 된 것만)

## 관련 노트
[[...]] · [[...]]
```

## 6단계 — 보고

1. 저장된 **전체 경로**
2. 되짚은 **노트 수**와 **주제 수**
3. **몇 문제 중 몇 개** 맞혔는지
4. **반복된 실수**가 있었으면 그것 한 줄 (가장 중요한 결과다)

## 주의할 점

- **지어내지 않는다.** 노트에 없는 실수를 "겪으셨죠" 라고 말하지 않는다.
  문제의 정답은 반드시 노트에서 인용할 수 있어야 한다.
- **클라우드(웹) 세션에서는 볼트를 읽을 수 없다.** 그때는 복습을 하지 말고
  "내 PC에서 다시 실행해 주세요" 라고 알린다.
- 노트가 5장 미만이면 복습 대신 **"아직 쌓인 게 적으니 몇 번 더 저장한 뒤에
  하시는 게 낫겠습니다"** 라고 말한다. 억지로 문제를 만들지 않는다.
- 복습은 **읽어주기가 아니라 꺼내보기**다. 요약만 하고 문제를 안 내면 이 스킬을
  쓴 의미가 없다.
